## Sade CSS ve BEM

**Vanilla CSS**, ayrı CSS dosyaları yazmak ve sınıf adlarını disiplinli bir kurala göre vermektir. **BEM** (Block Element Modifier), `blok__eleman--durum` biçiminde bir adlandırma sözleşmesidir. Hiçbir araca bağımlı değildir ve her yerde çalışır; amacı isim çakışmalarını ve özgüllük savaşlarını disiplinle önlemektir. Bedeli, disiplini herkesin sürdürmesi gerekmesidir. Framework kullanmayan projelerde ve eski kod tabanlarında görürsün. "Sınıf adlarını BEM'e göre verelim; şu an aynı ada sahip iki farklı stil var."

## CSS Modules

**CSS Modules**'te her bileşenin kendi CSS dosyası vardır ve sınıf adları derleme sırasında otomatik olarak benzersiz hâle getirilir. İsim çakışmasını **otomatik** çözer: disipline değil araca güvenirsin. Sade CSS yazmaya devam edersin ve çalışma zamanı maliyeti yoktur. React ve Next.js projelerinde yaygın ve güvenli bir varsayılandır. "CSS Modules kullanalım; sade CSS yazmaya devam ederiz ama çakışma riski kalmaz."

## Utility-first (Tailwind)

**Utility-first CSS**'te her biri tek bir işi yapan küçük sınıflar doğrudan HTML'e yazılır; en bilineni **Tailwind CSS**'tir. İki gerçek faydası var:

1. **Tasarım sistemine uymayı kolaylaştırır:** sınıflar önceden tanımlı bir ölçekten gelir, rastgele 17px yazamazsın.
2. **Kullanılmayan CSS birikmez:** stil bileşenin yanında durduğu için bileşeni silmek stilini de siler.

shadcn/ui gibi kopyala-yapıştır bileşen yaklaşımlarının temelidir. En yaygın eleştirisi HTML'in uzun sınıf listeleriyle dolmasıdır ("class soup"). Ölçeği yapılandırmada tanımlamazsan avantajı kaybolur. "Tailwind kullanalım ve spacing ölçeğimizi config'e yazalım; ölçek dışı değer kullanılamasın." Tailwind'in sürümleri arasında yapılandırma biçimi değişir; güncel sürümü kontrol et.

## CSS-in-JS

**CSS-in-JS**'te stiller JavaScript dosyalarının içinde yazılır. **Runtime** sürümleri (styled-components, Emotion) stilleri tarayıcıda çalışırken üretir; **zero-runtime** sürümleri (vanilla-extract, Panda CSS) derleme sırasında üretip statik CSS çıkarır. Stili bileşenle aynı dosyada tutar ve JavaScript değerlerine göre dinamik değiştirmeyi kolaylaştırır.

Bilmen gereken bir durum değişikliği var: kaynaklara göre **styled-components Mart 2025'te bakım moduna geçti** ve bakımcısı yeni projeler için önermediğini belirtti. Sebepler arasında React Server Components ile uyumsuzluk ve çalışma zamanı stil enjeksiyonunun performans maliyeti anılıyor. Kütüphane hâlâ çalışıyor; yani mevcut kodun tehlikede değil. Ama 2026'da yeni bir proje için varsayılan seçim değil. Önerilen yönler: CSS Modules, Tailwind ya da zero-runtime seçenekler. "Bu proje styled-components kullanıyor; devam edelim ama yeni bileşenleri CSS Modules'a alalım." Bu bilgi hızlı değişir; kullanmadan önce güncel durumu kontrol et.
