Form gönderimi için ayrı bir sunucu kurmak mı, yoksa ön yüz projesinin içinde bir sunucu işlevi yazmak mı? Modern meta-framework'ler üç yaklaşım sunar.

## API route

**API route (API yolu)**, ön yüz projesinin içinde tanımlanan, sunucuda çalışan endpoint'tir. Ayrı bir arka yüz projesi kurmadan sunucu tarafı kod yazmayı sağlar ve küçük/orta projelerde ayrı bir back-end ekibine olan ihtiyacı azaltır. Next.js ve benzeri meta-framework'lerde bulunur. "Form gönderimi için ayrı bir sunucu kurmayalım; API route yeter."

## Server action

**Server action**, ön yüz kodundan doğrudan çağrılabilen ama sunucuda çalışan işlevdir. Aradaki API katmanını yazma ihtiyacını ortadan kaldırır: form gönderimi için endpoint tanımlamak, adres yazmak ve yanıtı elle işlemek gerekmez. React Server Components ile birlikte gelen bir yaklaşımdır; modern Next.js projelerinde form ve mutasyonlarda kullanılır. "Bu formu server action ile bağlayalım; ayrı endpoint'e gerek yok."

**Kolaylık, doğrulama ve yetki kontrolünü atlamak için gerekçe değildir.** Server action da bir endpoint'tir; dışarıdan çağrılabilir. **Girdi doğrulaması ve yetki kontrolü orada da zorunludur.**

## BFF

**BFF (Backend For Frontend)**, her istemci türü (web, mobil) için ona özel şekillendirilmiş ince bir arka yüz katmanıdır. Ön yüzün ihtiyacı olan veriyi tek yerde toplar: üç farklı iç servisten veri çekip tek yanıt hâline getirir. Böylece ön yüz üç ayrı istek atmak zorunda kalmaz (under-fetching). Mikroservis mimarilerinde ve çok istemcili ürünlerde görülür. "Ekran üç ayrı servisten veri istiyor; BFF katmanı ekleyip tek istekte toplayalım."

- **Ekran çok sayıda servise bağlıysa** BFF ya da tek istekte toplama önerisinin neden yapıldığını anla.
