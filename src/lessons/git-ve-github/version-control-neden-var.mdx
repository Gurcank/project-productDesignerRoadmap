"Rebase ettim", "conflict çıktı", "main'e merge edildi". Bu cümleler her gün geçer ve kod yazmasan bile içinde olursun. Sebep şu: **Git yalnızca kodun değil, işin de kaydıdır.** Bir özelliğin ne zaman girdiği, kimin neyi değiştirdiği, bir hatanın hangi değişiklikle geldiği: hepsi burada.

Ürün ekibi açısından üç somut fayda var:

1. **Pull request incelemesine katılabilmek.** Tasarımın uygulanmış hâlini incelemek, bir PR üzerinde yorum yapmak kod yazmayı gerektirmez.
2. **Değişikliği takip edebilmek.** "Bu ne zaman böyle oldu?" sorusunun cevabı Git geçmişindedir.
3. **Konuşmayı anlamak.**

Bölümdeki temel kavramlar **eskimeyen** kategoridedir; Git yirmi yıldır aynı. Değişken olan, hangi iş akışının moda olduğu ve GitHub'ın ürün özellikleridir. **Söz dizimi yok:** komut adlarını yalnızca terimin kendisi oldukları için yazıyoruz ("rebase ettim" diye konuşulur), nasıl kullanılacaklarını değil.

## Sürüm kontrolü

**Version control system (sürüm kontrol sistemi)**, dosyalardaki değişikliklerin zaman içinde kaydedilmesini, geri alınabilmesini ve birden fazla kişinin aynı anda çalışabilmesini sağlar. Üç problemi birden çözer:

- **Geri dönebilmek:** bir şey bozulduğunda eski hâle dönmek.
- **Birlikte çalışabilmek:** iki kişinin aynı dosyayı ezmemesi.
- **"Neden?" sorusunu cevaplamak:** bu satır neden böyle yazılmış?

"Bu değişikliği geri alalım; geçmişte hangi commit'te girdiğine bakalım."

**Git**, dağıtık bir sürüm kontrol sistemidir: her geliştiricinin bilgisayarında projenin tam geçmişiyle birlikte bir kopyası bulunur. "Dağıtık" olması internet olmadan da çalışabilmeyi ve merkezî sunucu çökse bile geçmişin kaybolmamasını sağlar. Fiilî standarttır. Git olmadan GitHub olmaz, ama GitHub olmadan Git gayet çalışır. "Depo Git'te; GitHub'da barındırıyoruz."

<Case>

Demlik'in kodu GitHub'da duruyor; ekipte kod yazmayan herkes de oraya bakıyor:

1. **Geri dönmek:** Panel'in bir sürümü sipariş listesini boş gösterdi. Hangi değişikliğin getirdiği geçmişte göründü; dört dakikada geri alındı.
2. **Birlikte çalışmak:** Ece ve Emre ortak sipariş kartı bileşenine aynı hafta dokundu; ikisinin değişikliği ayrı dallarda kaldı, birleştirirken görüldü.
3. **Neden?** Ozan, Panel'de iptal düğmesinin neden ayrı bir menüye taşındığını sordu. Cevap, o değişikliğin pull request'indeki sezgisel değerlendirme notundaydı.
4. **Kayıt:** Leyla kampüs projesinin kilometre taşlarını sürüm etiketleriyle eşledi: "entegrasyon hazır" hangi koddu, belli.

</Case>
